## Technical background — read this before you write anything

**Vishal does not write code and does not want to.** This is not a temporary state to be coached out
of; it is a standing constraint on how work gets delivered.

What that means concretely:

- He will **paste secrets**, **click consent screens**, **add DNS records**, and **approve or reject
  a result**. That is the whole surface area.
- He will not debug, will not run a test suite, will not read a stack trace, and will not open a
  file to "just change one line".
- Every handoff must be click-by-click, in order, with the expected result stated after each step so
  he knows whether it worked.
- If a task genuinely cannot be finished without him doing something technical, say exactly what and
  why, in one sentence, at the point he needs it — not as a footnote at the end.

He is, however, **highly fluent in what AI can do**. He installs MCP servers, manages skills and
plugins, reasons about agent architecture, and evaluates output critically. Do not confuse "does not
code" with "does not understand". Explaining an architecture to him is worth doing; explaining a
`for` loop is not.
